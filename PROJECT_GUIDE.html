보호나라 보안공지 수집기

코드를 처음 보는 분도 전체 흐름을 따라갈 수 있도록, 프로그램이 어디서 시작하고 어떤 파일을 거쳐 JSON을 만드는지 설명합니다.

1. 프로그램이 하는 일

이 프로그램은 보호나라 RSS에서 새 보안공지 목록을 읽고, 각 공지 페이지를 방문해 분석에 필요한 정보를 JSON 파일로 정리합니다.

  • RSS에서 게시글 제목, 주소, 게시 날짜를 읽습니다.
  • 각 게시글 페이지에서 CVE, 영향을 받는 제품·버전, 대응 방법 등을 찾습니다.
  • 공지별 JSON을 output/articles/에 저장합니다.
  • 완성된 JSON 배열도 터미널 화면에 출력합니다.
현재 범위: 데이터베이스와 LLM 연동은 없습니다. 지금은 공지를 수집·파싱하고 JSON으로 저장하는 역할까지만 합니다.
중요: 찾지 못한 CVE나 제품을 추측해서 채우지 않습니다. 확인이 필요하면 JSON의 review_required와 warnings에 표시합니다.

2. 실행하면 어떤 순서로 움직이나요?

프로젝트 폴더에서 python -m boho_rss를 실행하면 아래 순서대로 진행됩니다.

① 시작__main__.py
명령줄 옵션과 설정을 읽음
② 요청 준비http_client.py
HTTP 요청과 재시도 처리
③ RSS 읽기rss.py
공지 목록을 FeedItem으로 변환
④ 상세 분석article.py
페이지 HTML에서 필요한 값 추출
⑤ 결과 만들기collector.py
JSON 파일 저장 및 결과 반환

조금 더 자세히 보면, 시작 파일이 수집기를 만들고, 수집기가 HTTP 클라이언트와 파서 함수를 불러 사용합니다.

명령 실행
  └─ __main__.py: main()
       ├─ settings.py: load_settings()
       ├─ http_client.py: BohoHttpClient(settings)
       └─ collector.py: Collector(settings, client).collect()
            ├─ client.get(RSS 주소)
            ├─ rss.py: parse_rss(RSS 내용)
            └─ 공지마다 반복
                 ├─ client.get(공지 URL)
                 ├─ article.py: parse_article(HTML, 공지 정보, URL)
                 └─ collector.py: _save_article(파싱 결과)

화살표는 “이 파일이 저 파일의 기능을 가져와서 사용한다”는 뜻입니다. 예를 들어 collector.py 윗부분에 from boho_rss.article import parse_article라고 적혀 있으면, collector가 article 모듈의 함수를 가져다 씁니다.

3. 폴더와 파일은 각각 무슨 역할인가요?

프로젝트 폴더
├── boho_rss/__main__.py 실행 시작점
├── boho_rss/collector.py 수집 순서와 JSON 저장
├── boho_rss/article.py 공지 HTML 파싱
├── boho_rss/rss.py RSS XML 파싱
├── boho_rss/http_client.py 웹 요청
├── boho_rss/settings.py 설정 읽기
├── boho_rss/models.py RSS 게시글 데이터 모양
├── config.json RSS 주소와 요청 설정
├── requirements.txt 설치할 외부 라이브러리 목록
├── examples/sample_advisory.json JSON 형식 예시
└── output/articles/ 수집된 JSON 파일
파일쉬운 설명누가 사용하나요?
__main__.py프로그램의 입구입니다. 옵션을 받고 설정을 읽은 뒤 전체 작업을 시작합니다.사람이 명령을 실행할 때 Python이 시작합니다.
collector.pyRSS를 가져오고, 각 상세 페이지를 읽게 하고, 파싱한 결과를 파일로 저장합니다.__main__.py가 Collector를 만듭니다.
article.py공지 HTML 안에서 제목, CVE, 제품과 버전 같은 값을 찾습니다.collector.py가 parse_article()을 호출합니다.
rss.pyRSS라는 XML 문서를 읽어 공지 목록으로 바꿉니다.collector.py가 parse_rss()를 호출합니다.
http_client.py웹사이트에 요청하고, 잠시 기다리거나 실패한 요청을 재시도합니다.__main__.py가 만들고 collector.py가 사용합니다.
settings.pyconfig.json을 읽어 프로그램이 쓸 설정 객체를 만듭니다.__main__.py가 load_settings()를 호출합니다.
models.pyRSS에서 얻은 게시글 한 건을 표현하는 FeedItem 자료형이 있습니다.rss.py가 만들고 article.py가 입력으로 받습니다.

4. 클래스와 함수 안내

함수는 “입력을 받아 정해진 일을 하는 코드 묶음”, 클래스는 “관련 데이터와 기능을 함께 쓰기 위한 설계도”라고 생각하면 됩니다.

실행과 수집

이름위치하는 일호출하는 곳
build_parser()__main__.py--config, --limit 같은 명령 옵션을 정의합니다.main()
main()__main__.py설정을 읽고 클라이언트와 수집기를 만든 뒤, 결과를 화면에 JSON으로 출력합니다. 오류가 나도 HTTP 연결을 닫습니다.프로그램을 실행하면 마지막의 main() 호출이 시작합니다.
Collectorcollector.py전체 수집 흐름을 관리하는 클래스입니다. 설정과 HTTP 클라이언트를 보관합니다.main()이 만듭니다.
Collector.collect(limit)collector.pyRSS를 읽고 각 공지를 순서대로 상세 조회·파싱·저장합니다. 제한이 있으면 앞에서부터 해당 건수만 처리합니다.main()
Collector._save_article(article)collector.py한 공지 결과를 output/articles/<게시글ID>.json에 UTF-8로 저장합니다.collect()

웹 요청과 RSS

이름위치하는 일호출하는 곳
Settingssettings.pyRSS 주소, 출력 폴더, 제한 시간, 재시도 횟수 같은 설정을 담는 자료형입니다.load_settings()가 만들고 다른 객체가 받습니다.
load_settings(path)settings.pyJSON 설정 파일을 읽고 값과 경로를 확인해 Settings를 돌려줍니다.main()
HttpClienthttp_client.py“주소를 주면 HTTP 응답을 돌려준다”는 약속을 나타냅니다. 수집기는 실제 요청 방식의 세부사항을 몰라도 됩니다.Collector가 사용할 수 있는 클라이언트의 형태입니다.
BohoHttpClienthttp_client.py그 약속을 실제로 구현합니다. 타임아웃, 재시도, 사용자 에이전트와 요청 간격을 설정합니다.main()이 만들고 Collector가 사용합니다.
BohoHttpClient.get(url)http_client.py주소를 요청하고 성공하지 않은 HTTP 응답이면 오류를 발생시킵니다.Collector.collect()
normalize_detail_url(url)http_client.py보호나라 보안공지 주소에 필요한 menuNo=205020가 없으면 추가합니다.BohoHttpClient.get()
FeedItemmodels.py공지 한 건의 ID, 제목, 주소, 게시 날짜를 담습니다.parse_rss()가 만들어 parse_article()에 전달합니다.
parse_rss(xml_bytes)rss.pyRSS XML을 읽어 중복 없는 FeedItem 목록으로 바꿉니다. 읽을 수 없는 RSS이면 FeedParseError를 발생시킵니다.Collector.collect()

공지 HTML 파싱

이름위치하는 일
parse_article(html, item, detail_url)article.py공지 페이지를 읽고 최종 JSON에 들어갈 Python 딕셔너리를 만듭니다. 공지 본문이 아닌 페이지라면 ArticleParseError로 알려줍니다.
_read_sections(content)article.py본문 문단에서 개요, 설명, 대응 방안처럼 표시된 문장을 찾습니다.
_read_products(content)article.py표의 열 제목을 확인해 제조사, 제품, 영향 버전, 해결 방법을 행별로 읽습니다. CVE는 같은 표 행에서 찾은 것만 제품과 연결합니다.
_read_references(content, detail_url)article.py본문 문단과 목록 안의 링크를 참고 링크로 정리합니다.
_read_response_after_table(content)article.py별도 대응 방안 문단이 없을 때 제품 표 다음의 업데이트·패치 권고 문장을 찾습니다.
ArticleParseErrorarticle.py게시글 HTML 구조가 없거나 제목·본문을 찾지 못했을 때 사용하는 오류 이름입니다. main()이 이를 잡아 오류 메시지를 출력합니다.

함수 이름 앞의 밑줄(_)은 보통 “이 파일 내부에서만 쓰는 보조 기능”이라는 표시입니다. 예: _read_products()는 주로 parse_article()를 돕습니다.

5. 실행 방법

터미널에서 프로젝트 폴더로 이동한 다음 아래 명령을 실행합니다.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m boho_rss

첫 세 줄은 가상 환경을 만들고 필요한 패키지를 설치하는 준비입니다. 이미 설치했다면 다시 할 필요 없이 마지막 명령으로 실행하면 됩니다.

명령뜻
python -m boho_rssRSS의 공지를 가져옵니다. 결과 JSON 배열을 터미널에 출력하고 공지별 파일도 저장합니다.
python -m boho_rss --limit 3RSS 앞쪽의 공지 최대 3건만 처리합니다.
python -m boho_rss --config config.json사용할 설정 파일 경로를 지정합니다.

설정은 config.json에서 관리합니다. rss_url은 RSS 주소, output_dir는 JSON 저장 폴더입니다. 요청 제한 시간과 재시도 횟수도 조절할 수 있습니다.

성공하면: output/articles/게시글ID.json 파일이 생성되거나 최신 내용으로 바뀝니다. 예를 들어 게시글 ID가 72289라면 output/articles/72289.json입니다.
주의: 실행 때마다 RSS에 보이는 공지를 다시 요청하고 같은 ID 파일은 덮어씁니다. 실행 도중 문제가 생기면 오류 메시지가 나오고 종료 코드 1을 반환합니다.

6. 만들어지는 JSON을 읽는 방법

JSON은 프로그램들이 쉽게 읽도록 데이터를 이름표와 값으로 표현한 형식입니다. 중괄호 { }는 공지 한 건, 대괄호 [ ]는 여러 값의 목록을 뜻합니다.

{
  "post_id": "72289",
  "title": "공지 제목",
  "cve_ids": ["CVE-2026-12345"],
  "affected_products": [
    {
      "product_name": "제품 이름",
      "affected_version": "취약한 버전",
      "fixed_version_or_action": "해결 버전 또는 조치",
      "cve_ids": ["CVE-2026-12345"]
    }
  ],
  "review_required": false,
  "warnings": []
}
필드의미
post_id, title, published_at, url공지의 ID, 제목, 게시일, 원문 주소입니다.
overview, vulnerability_description, response본문에서 찾아낸 개요, 취약점 설명, 대응 안내입니다.
cve_ids공지 전체 본문에서 발견한 CVE 목록입니다.
affected_products영향받는 제품 행들의 목록입니다. 각 항목에는 제품명·버전과 그 표 행에 직접 적힌 CVE가 들어갑니다.
references공지 본문에 있는 참고 링크입니다.
body_text파싱 결과를 나중에 다시 확인할 수 있도록 남긴 본문 텍스트입니다.
review_required, warnings자동으로 확인하기 어려운 정보가 있는지와 확인할 이유를 나타냅니다.

최상위 cve_ids는 공지 전체의 CVE 목록이고, affected_products 안의 CVE는 제품별 연결 정보입니다. 두 곳에 CVE가 보이는 것은 목적이 달라서이며, 제품과 CVE의 연관성을 분석할 때 제품별 목록을 사용하면 됩니다.

실제 공지의 긴 본문을 공개 저장소에 그대로 복사하지 않고, 예시 JSON에는 구조를 이해하는 데 필요한 일부 필드만 담았습니다. 실행해서 만들어지는 전체 결과는 로컬 output/articles/에 저장됩니다.
